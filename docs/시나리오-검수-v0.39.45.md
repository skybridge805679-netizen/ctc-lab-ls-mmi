# 시나리오 검수 (v0.39.45)

대상: 부본선 대피 5종(`scenarios.js`) · 비상시 조치 9종(`emergency.js`)과 이를 바꾼 FTS 내장 문제(`fts-builtins.js`).
방법: ① 원문 대본의 관계열차·지시와 시작 배치·열차 움직임을 한 줄씩 대조 ② 시작 진로를 문제마다 출력해 확인
③ 14문제를 모범 답안으로 끝까지 풀기 ④ 「신호 확인 출발」 통보 뒤 열차가 실제로 떠나는지 확인.

## 고친 것

### 1. 시작 진로가 엉뚱하게 잡혀 있던 문제 (전 시나리오 공통)

시작할 때 진행을 보이는 신호의 진로를 「번호가 작은 것」으로 골랐다. 그래서 정상 진로 대신 건넘 진로가 섰다.

| 문제 | 예전 시작 진로 | 지금 |
|---|---|---|
| 02 동묘앞 충돌 | 종각 2A-**1T** (상선 열차를 하선 승강장으로) | 종각 2A-2T, 4A-B046T |
| 03 석수 충돌 · 06 화재 3종 | 안양 3B-**B655T** (운행선 변경용 진로가 처음부터), 안양 2B-**6T** | 안양 3B-B981T, 3C-B655T |
| 04 금정 사상사고 | 안양 4B-**B660T** (운행선 변경용 진로가 처음부터) | 안양 4B-B984T, 군포 1A-1T · 1B-2T |
| 05 가산 차량고장 | 금천구청 3B-**B639T** (운행선 변경용), 구로 2B-**1T** | 금천구청 3B-B963T · 3C-B639T · 2B-4T |
| 05-1 | 금천구청 3B-**B639T** | 금천구청 3B-B963T, 구로 2A-5T |

규칙: 장내 신호는 그 신호가 선 선로로, 출발 신호는 그 선로의 본선 폐색으로 가는 정상 진로를 고른다.
정상 진로의 도착 선로에 열차가 서 있으면 그 장내 신호는 정지로 둔다(다른 선로로 돌리지 않는다).

### 4. 대피

금천구청 1번 대피: 후속열차가 하1선 3T를 지난 뒤 하2선 폐색(B968T) 열번창으로 건너뛰었다.
금천구청 화면에는 하1선 출구 쪽 열번창이 없으므로 3T에서 4C 진로로 바로 관제구간 밖으로 나간다.

## 확인만 하고 그대로 둔 것

- 「각 역 3분 추가정차」만 지시받는 선행 열차(K1131·K1133·K0805·K0807·K1204·K1206 등)는 LS에 놓지 않는다. 관제구간 안 위치가 원문에 없다.
- 02 K0604: 원문은 「동묘앞역과 장내신호기 사이 정차」지만 K0602와 같은 열번창(2T)에 겹쳐 놓는다(열차번호 중복 알람 재현).
- 04 K0809: 원문 대화는 「승강장 진입 전 정차」지만 시험 장비 표시(베타 피드백)에 맞춰 2T에 놓는다.
- 출발 지시를 받은 열차는 역을 벗어나면 화면에서 사라진다(다음 역까지 이어 달리지 않는다).
