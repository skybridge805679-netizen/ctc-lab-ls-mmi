# v0.21.0 — Apple Silicon Mac·Windows 데스크톱 앱

기존 시뮬레이터를 Electron 45 앱으로 실행한다. 배선도·진로·쇄정·열차 운행·그래프·스케줄·시나리오·오르페이아 디자인은 기존 코드를 그대로 사용하며 브라우저 실행도 유지한다. Intel Mac 빌드는 제공하지 않는다.

## 설치와 실행

[GitHub Releases](https://github.com/skybridge805679-netizen/ctc-lab-ls-mmi/releases)에서 운영체제에 맞는 파일을 받는다. 두 운영체제의 빌드·시험에 성공한 버전만 자동 게시된다. 빌드 중이거나 실패하면 새 릴리스는 게시되지 않으며 [Actions](https://github.com/skybridge805679-netizen/ctc-lab-ls-mmi/actions/workflows/desktop.yml)에서 결과를 확인한다.

| 환경 | 설치본 | 압축 실행본 |
|---|---|---|
| M1 등 Apple Silicon Mac | `ORPHEIA-CTC-LAB-0.21.0-mac-arm64.dmg` → 앱을 Applications로 이동 | `mac-arm64.zip` |
| Windows x64 | `ORPHEIA-CTC-LAB-0.21.0-win-x64.exe` → 사용자 계정에 설치 | `win-x64.zip` → 압축 전체를 풀고 `ORPHEIA CTC LAB.exe` 실행 |

시뮬레이터와 이미지 에셋을 설치본에 포함한다. Node.js·Python·개발 서버·인터넷 연결은 설치 후 실행에 필요하지 않다. 웹의 레퍼런스 원본 전체와 과거 실행본은 앱에 중복 포함하지 않으며 GitHub에 유지한다.

공인 배포 서명 인증서·Apple 공증 자격은 현재 구성에 없다. Mac 빌드는 ARM 실행을 위한 ad hoc 서명을 수행하지만 개발자 신원 검증이나 Apple 공증은 아니다. 최초 실행 시 macOS의 개인정보 보호 및 보안에서 해당 앱의 실행을 허용하거나 Windows의 게시자 확인이 필요할 수 있다. 운영체제 보안 기능을 전역으로 끌 필요는 없다.

## 두 창 조작

실행 시 LS·MMI가 각각 네이티브 창으로 열린다. 각 모니터로 옮겨 사용한다. `실습 화면` 메뉴에서 창 포커스·MMI 재분리·한 화면 합치기·기록 저장·전체 화면을 선택한다. `⌘/Ctrl+1`은 LS, `⌘/Ctrl+2`는 MMI, `⌘/Ctrl+S`는 조작 기록 저장이다. 편집 메뉴의 복사·붙여넣기도 지원한다.

붉은 알람은 MMI에 표시하며 LS 조작을 막지 않는다. LS 제어 확인창과 우클릭 메뉴는 LS에 유지한다. MMI를 닫으면 입력·로그·알람을 유지하며 LS로 합쳐진다. LS를 닫거나 앱을 종료하면 전체 실행을 종료한다.

두 창의 위치·크기·최대화 여부를 사용자별 `window-layout.json`에 저장한다. 모니터가 연결 해제되거나 해상도가 바뀌면 사용 가능한 화면 안으로 배치를 보정한다. 처음 실행할 때 두 번째 모니터가 있으면 MMI를 그 모니터에 배치한다. 저장 위치는 Electron의 사용자 데이터 경로(macOS Application Support, Windows AppData)다.

**창 배치 기억은 실습 진행 자동 저장과 다르다.** 관제 엔진은 아직 LS 렌더러에 한 번 실행되며 독립 백그라운드 엔진으로 분리한 단계는 아니다. 실습 세션의 자동 복구·자동 업데이트·서명/공증 배포는 이번 버전에 포함하지 않는다. 필요한 기록은 종료 전 내보낸다.

## 개발과 빌드

Node.js 24 LTS와 npm을 사용한다.

```sh
npm ci
npm start
npm test
npm run test:desktop
```

Mac에서는 `npm run dist:mac`, Windows에서는 `npm run dist:win`으로 해당 플랫폼의 설치본과 ZIP을 `dist/`에 만든다. Mac DMG와 ad hoc 서명은 macOS에서, Windows 설치본은 Windows에서 만드는 것이 기본 경로다. Electron 실행파일 다운로드가 필요하므로 최초 개발 설치와 빌드는 네트워크를 사용한다.

`.github/workflows/desktop.yml`은 main 변경과 수동 실행을 지원한다. macOS·Windows에서 Node 시험·실제 Electron 두 창 시험·패키징·ASAR 구성 검사를 실행하고, Windows와 ARM64 Mac 러너에서는 패키징한 실행파일도 시험한다. macOS 러너가 Intel이면 소스 앱 실행 시험과 ARM64 교차 빌드까지만 수행한다. 양쪽 성공 후 새 버전 태그·릴리스에 DMG·EXE·ZIP을 게시하며 기존 버전 다운로드는 덮어쓰지 않는다. GitHub Actions 사용 권한·러너 가용성이 필요하다.

렌더러의 Node 통합은 끄고 context isolation·sandbox를 켠다. 외부 페이지 탐색과 임의 팝업은 차단하며 신뢰한 MMI 창만 허용한다. 앱 파일은 ASAR에 담는다. 설치본에는 개발용 Playwright나 서버를 포함하지 않는다.

## 확인한 범위

Linux 클라우드에서 실제 Electron과 ASAR 패키징 실행본의 자동 두 창 생성·공유 제어·MMI 알람 중 LS 조작·그래프·창 복원·배치 저장을 시험했다. 테스트 환경의 커널 제한 때문에 Linux 자동화 실행에만 `--no-sandbox`를 사용하며 배포 실행 설정에서는 사용하지 않는다. Node 시험 34개, 기존 두 창 브라우저 시험 1440·1920px를 통과했다.

Windows ZIP 및 macOS ARM64 ZIP의 교차 패키징과 실행파일 아키텍처도 검사한다. Linux에서 두 운영체제의 실제 실행·DMG 생성·Mac 서명/공증을 검증했다고 간주하지 않는다. Windows EXE의 교차 빌드는 Linux의 Wine 부재로 완료하지 못했다. 설치본 생성과 실제 운영체제 결과는 GitHub Actions에서 확인해야 한다. 모바일 지원·모바일 시험은 없다.
