# 15개 제어역 · 온라인 열차그래프 · 스케줄 관리

v0.5, 2026-10-20. 사용자 요청에 따라 **LS/MMI 역 전환은 관제에서 제어하는 15개 연동역만** 제공한다. 온라인 스케줄과 다이아는 **중간역을 포함한 전체 33개 역**을 사용한다.

역 탭·LS 표시역·MMI 제어역은 같은 선택을 공유한다. 각 역의 모드·진로·전환기·기록은 별도 상태이며, 역을 왕복해도 유지된다. 제어 확인창이 열린 동안에는 역을 바꾸지 않는다. 기존 지하서울 9개 과제를 시작하면 지하서울로 전환한다.

39개 진로는 모든 실설비 진로의 전수 목록이 아니다. 배선에서 확인한 기본 번호와 대본의 일부 진로를 등록했다. 추가 역은 보수적으로 역 안의 진로를 하나만 설정하도록 보호하며, 진로가 있으면 수동 전환기를 거부한다. 상세 선형을 확인하지 못한 진로는 잘못된 녹색 선을 그리지 않고 설정 상태와 신호 진행 표시로 표현한다. 정확한 등색 조합·정반위 조건표·전환기 명칭 클릭 영역·모든 입환진로는 후속 고증 대상이다.

`network.js`는 역·신호·기본 진로·원본 슬라이드를 연결한다. 지하서울의 기존 상세 데이터는 `core.js`에서 유지한다. `assets/stations/SOURCES.json`에 추출 이미지 해시를 기록했고 PPTX 미디어와 바이트 일치를 검증했다.

## 온라인 열차그래프 사용

1. MMI **열차 그래프 → 온라인 열차그래프 열기**.
2. 표시할 시작역·종착역·시작시각·30/60/120분 시간 범위 및 역축 간격을 선택한다.
3. 열차번호 검색, 선택 열차 목록 또는 그래프의 열차선을 눌러 시각표를 조회한다.
4. 변경역과 지연분을 지정하면 그 역 이후 시각이 바뀌고 계획선·상세표가 함께 갱신된다.
5. 전체 운휴/복원, 1/10/60배 진행, 현재시각 보기, JSON 저장을 사용할 수 있다. 기존 일시정지·+10초와 같은 가상시계를 쓴다.

시간은 가로축, 역 순서는 세로축이다. 최초 계획은 점선, 현재 계획은 상하행 색상 실선, 가상 위치는 점, 현재시각은 붉은 선으로 표시한다. 제어역 이름은 LS 전환으로 연결하고 중간역 이름은 조회 표기로 둔다.

초기 12개 열차는 **교육용 시각표**다. 기본 예시는 08:00부터 상하행 각각 6분 간격, 역간 2분·정차 30초로 구성하며 실제 운행 시각표·실적 데이터가 아니다. 축은 실제 킬로정 대신 역 순서에 따라 같은 간격을 쓴다. 위치점은 시각표 보간이며 LS 점유·신호 현시와 실제 열차 이동을 연동한 모델이 아니다.

## 온라인 열차스케줄 관리

MMI **열차스케줄 → 온라인 열차스케줄 관리**에서 수정·복사·생성 모드를 선택한다. 시발·종착 선택과 경유역 정보에는 다음 전체 33개 역이 들어간다.

청량리 → 제기동 → 신설동 → 동묘앞 → 동대문 → 종로5가 → 종로3가 → 종각 → 시청 → 지하서울 → 서울 → 남영 → 용산 → 노량진 → 대방 → 신길 → 영등포 → 신도림 → 구로 → 가산디지털 → 독산 → 금천구청 → 석수 → 관악 → 안양 → 명학 → 금정 → 군포 → 당정 → 의왕 → 성균관대 → 화서 → 수원.

- **조회·수정:** 열차번호를 검색하고 경유역별 도착·출발시각, 번선·진로 메모, 열차등급, 차량수, 연계열차, 전체 운휴를 편집한다. 편집 적용 전에는 모델이 바뀌지 않는다. 편집 취소·다시 조회는 임시 내용을 버린다.
- **생성:** 새 열차번호·시발·종착·시작출발시각을 지정하고 열차패턴정보를 적용한다. 기본 전역정차 패턴을 확인·수정한 뒤 편집 적용한다. 반대 방향 및 비연동역 시발·종착도 지원한다.
- **복사:** 원본을 선택하고 새로운 열차번호와 시작출발시각을 지정한다. 원본의 현재 시각을 기준으로 간격을 보존해 복사하고 원본을 유지한다. 운휴된 원본에서도 운행 스케줄을 복사할 수 있다.
- **운휴:** 전체 운휴를 적용하면 다이아와 관리 화면에 함께 반영한다. 이 연습에는 열차 삭제나 기존 열차번호 직접 변경 기능을 제공하지 않는다.
- 중복 번호·잘못된 역 순서·도착/출발 역전·운행일을 벗어난 시각·잘못된 차량수를 검증한다. 오류가 있는 편집은 전체를 거부하고 원래 데이터를 유지한다. 다이아에서 변경한 뒤 남아 있던 편집을 적용하면 재조회하도록 요구한다.

다이아와 관리 화면은 같은 데이터를 사용한다. 다이아 JSON 저장에는 생성·복사한 열차와 변경 이력도 포함된다. 현재는 브라우저 메모리의 단일 교육 운행일이며 새로고침 후 복원·실제 온라인 DB 연결·어제/내일 조회·패턴 DB·부분 운휴·분할합병과 기능열차 상세는 미구현이다. 번선·진로 메모는 LS 명령을 실행하지 않는다.
