# v0.34.0 — 상황별 대응 요령(상황 변경) · 교수/교육생 화면 분리 (2026-10-31)

## 상황 변경 (비상시조치 평가 시 상황별 대응 요령)
능동형 문제를 만들 때 가장 먼저 봤어야 할 자료가 「비상시조치 평가 시 상황별 대응 요령」이었다. 실기 평가에서 감독관은 기본 시나리오 도중에 상황을 바꾼다(조치 지연, 회송 불가, 탈선, 자력 운행 가능 등). 교육생은 그 변화에 맞춰 지시 순서와 내용을 바꿔야 한다.

- **형식**: 문제에 `branches`(상황 변경)를 추가했다.
  - 켜지는 방식: 교수가 모니터링에서 **[주입]** 하거나, `when` 조건이 맞으면 켜진다.
  - 켜지면: 분기의 목표·통보·반응이 더해지고, `drop`의 기본 항목이 빠진다.
  - 조건 `branch`로 다른 항목이 분기를 기다리게 할 수 있다.
  - 형식 문서: `docs/FTS-시나리오-형식.md`.
- **데이터**: `simulator/engine/emergency-branches.js`. 원문 줄 범위를 그대로 인용하고, 시작 줄이 원문과 다르면 오류를 낸다.

  |---|---|
  | 사상사고 (04) | 상황1 사고조치 지연 — 18·19 대체<br>상황2 A1005 근접 — 15-A<br>상황3~5 명학역 정차위치 변경 |
  | 차량고장 (05) | 상황1 고장대차 차단·정상운행<br>상황2 정거장 진입 전 정차 |

  - 원문 끝의 「관제사 선제적 운행선 변경(단선지령식) 요청」은 점수 없는 선택 통보(`proactive`)로 기록한다.
- **화면**
  - 모니터링: 상황 변경 목록에서 [주입]을 누를 수 있고, 원문을 펼쳐 볼 수 있다. 몇 개의 기본 항목이 빠지는지도 보인다.
  - 문제관리: 「상황 변경」 탭에서 분기 목록을 보고, JSON으로 등록·교체한다.

### 원문을 따르지 못한 부분
- `drop`으로 빼는 것은 원문이 번호로 바꾼다고 적은 통보(예: 사상사고 18·19, 동묘 8 / 1·5·6·11·24)뿐이다. 「정상운행 가능」으로 필요 없어진 구원 조치(구원열차 번호 수정·이동·삭제, 합병 통보)도 뺀다.
  - 그 밖의 「일부 변경」(예: 동묘 #21)은 기본 항목을 남기고 분기 통보를 더했다. 교수가 판단한다.
- 원문의 「1B·4C 진행 유지」(사상사고 상황2)와 「지하서울 3A·2A 정지」(시청침수 원거리 접근)는 조작 목표로 넣지 않았다. 이 시뮬레이터의 기본 시나리오 초기 진로에서는 해당 신호기 진로가 설정되지 않아 취소할 신호가 없기 때문이다. 통보와 원문으로만 남겼다.
- 원문에 나오는 A1005, K1037, K399 같은 열차는 시뮬레이터 열번창에 없어 열차 움직임을 만들지 않았다.

## 교수 프로그램과 교육생 화면 분리
- **FTS 제어통제 로그**: FTS의 기록(교육 시작·상황 시작·현상 발생·상황 변경·문제 종료 등)을 MMI 로그에 남기지 않는다. 독립 엔진의 FTS 로그(`snapshot.fts.logs`, 체크포인트 보존)와 FTS 모니터링 화면의 「제어통제 로그」에만 남긴다.
  - 교육용 「알람 발생」 현상은 교육생이 보는 시스템 알람이므로 MMI 알람에 그대로 뜬다.
- **문제 발생 화면**: MMI 안의 창이 아니라 교육생이 보는 독립 창이다. 데스크톱에서는 「ORPHEIA · 문제 발생」 창이 따로 뜨고 창 위치를 기억한다.

## 화면 정리
- FTS 창이 큰 창에서도 아래까지 채워진다. 예전에는 고정 높이 때문에 아래가 비었다.
- MMI 상단의 설비 장애 · CDRS 해소안 · 선로망 · 운전정리 대장 · 자동제어 버튼을 뺐다. 각 기능 창은 그대로 있다.
- LS 상단의 ↗ MMI 창 · ↗ 열차그래프 창 · 진로·연습 버튼을 뺐다. MMI·열차그래프·FTS는 실습 화면 메뉴(Ctrl/⌘+2·3·4)로 연다.
