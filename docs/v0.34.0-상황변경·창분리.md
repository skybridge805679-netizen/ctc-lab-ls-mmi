# v0.34.0 — 상황별 대응 요령(상황 변경) · 교수/교육생 화면 분리 (2026-10-31)

## 상황 변경 (비상시조치 평가 시 상황별 대응 요령)
능동형 문제를 만들 때 가장 먼저 봤어야 할 자료가 「비상시조치 평가 시 상황별 대응 요령」이었다. 실기 평가에서 감독관은 기본 시나리오 도중에 상황을 바꾼다(조치 지연, 회송 불가, 탈선, 자력 운행 가능 등). 교육생은 그 변화에 맞춰 지시 순서와 내용을 바꿔야 한다.

- **형식**: 문제에 `branches`(상황 변경)를 추가했다.
  - 켜지는 방식: 교수가 모니터링에서 **[주입]** 하거나, `when` 조건이 맞으면 켜진다.
  - 켜지면: 분기의 목표·통보·반응이 더해지고, `drop`의 기본 항목이 빠진다.
  - 조건 `branch`로 다른 항목이 분기를 기다리게 할 수 있다.
  - 형식 문서: `docs/FTS-시나리오-형식.md`.
- **데이터**: `simulator/engine/emergency-branches.js`. 원문 줄 범위를 그대로 인용하고, 시작 줄이 원문과 다르면 오류를 낸다.

  - 원문 끝의 「관제사 선제적 운행선 변경(단선지령식) 요청」은 점수 없는 선택 통보(`proactive`)로 기록한다.
- **화면**
  - 모니터링: 상황 변경 목록에서 [주입]을 누를 수 있고, 원문을 펼쳐 볼 수 있다. 몇 개의 기본 항목이 빠지는지도 보인다.
  - 문제관리: 「상황 변경」 탭에서 분기 목록을 보고, JSON으로 등록·교체한다.

### 분기 상황을 LS에 그대로 만든다
분기는 통보만 바꾸는 것이 아니다. 주입하는 순간 원문이 말하는 열차와 진로가 LS에 생긴다.
- **사상사고 상황2 (A1005 근접)**
  - A1005가 안양역 1B 장내 앞(B658T)에 나타나고, 연동을 지키며 1B-3T → 4C-B660T로 지나가려 한다.
  - K0811용 4B-B660T가 서 있으면 오버랩·경합 때문에 들어오지 못한다. 교육생이 4B를 해정해야 지나간다.
  - 역이 AUTO면 1B·4C가 자동 진로로 서고, CCM이면 교육생이 직접 설정해야 한다(「1B, 4C 진행 확인 유지」).
  - K0811 운행선 변경(4B-B660T)과 군포 1B-1T는 A1005가 지나간 뒤에만 인정한다.
- **시청침수 K1008 장내 외방 접근**: K1008을 지하서울 2A 접근구간(B067T)에 두고 2A-2T를 진행으로 세운다. 2A를 취소하면 접근쇄정 90초가 걸린다.
- **시청침수 K1008 원거리 접근**: K1008을 접근구간 밖(서울 B069T)에 두고 2A-2T를 세운다. 취소해도 접근쇄정이 걸리지 않는다.
- **K1006 이미 통과 · G607 통과 후**: 해당 열차번호가 이미 지나간 상태로 LS에서 빠진다.
- **FTS 상황 반응의 열차 운행이 연동을 지킨다.** 이전에는 수동 인계처럼 진로 없이 옮겨졌다. 이제는 경합·오버랩·제어모드를 지키며, 막히면 기다린다.
- 원문에 나오는 K1037·K399 같은 열차는 통보 대상으로만 등장한다. 열번창 상황이 필요한 분기에는 위처럼 열차와 진로를 만들었다.

## 단선지령식은 LS 조작만으로
실제 프로그램처럼 단선지령식은 LS에서 시행·복귀한다(CCM → 반대선으로 나가는 진로 설정 → 열번 이동). 엔진이 LS 상태에서 단선 운전을 알아낸다.
- 어떤 역간 선로로 **반대 방향으로 나가는 진로**(예: 종각 53-B045T)가 서 있으면, 맞은편 역에서 같은 선로로 나가는 정방향 진로를 막는다(정면 충돌 방지).
- 진행 방향과 **반대인 열차번호**가 그 구간 열번창에 있으면, 그 역간을 단선 운전 구간으로 보고 양끝 진로를 보호한다.
- 진로가 풀리고 열차가 빠지면 보호도 끝난다.
- 선로망 창(구간 점유표 · 폐색 검사 끄기 · 단선지령식 시행/복귀 버튼)은 실제 프로그램에 없는 기능이라 없앴다.
- 비상 01 대본의 초기 진로가 종각 4A를 반대 방향 진로(4A-B045T)로 잡던 오류도 고쳤다. 정방향(4A-B046T)을 고른다.

## 교수 프로그램과 교육생 화면 분리
- **FTS 제어통제 로그**: FTS의 기록(교육 시작·상황 시작·현상 발생·상황 변경·문제 종료 등)을 MMI 로그에 남기지 않는다. 독립 엔진의 FTS 로그(`snapshot.fts.logs`, 체크포인트 보존)와 FTS 모니터링 화면의 「제어통제 로그」에만 남긴다.
  - 교육용 「알람 발생」 현상은 교육생이 보는 시스템 알람이므로 MMI 알람에 그대로 뜬다.
- **문제 발생 화면**: MMI 안의 창이 아니라 교육생이 보는 독립 창이다. 데스크톱에서는 「ORPHEIA · 문제 발생」 창이 따로 뜨고 창 위치를 기억한다.

## 화면 정리
- FTS 창이 큰 창에서도 아래까지 채워진다. 예전에는 고정 높이 때문에 아래가 비었다.
- MMI 상단의 설비 장애 · CDRS 해소안 · 선로망 · 운전정리 대장 · 자동제어 버튼을 뺐다. 선로망 창은 기능째 없앴고, 나머지 창은 그대로 있다.
- LS 상단의 ↗ MMI 창 · ↗ 열차그래프 창 · 진로·연습 버튼을 뺐다. MMI·열차그래프·FTS는 실습 화면 메뉴(Ctrl/⌘+2·3·4)로 연다.
