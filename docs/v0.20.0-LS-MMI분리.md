# v0.20.0 — LS·MMI 두 창

상단 **↗ MMI 새 창**을 누르면 LS는 현재 창에 남고 MMI는 별도 브라우저 창으로 열린다. 각 창을 원하는 모니터로 옮겨 사용한다. 기존 한 화면 구성도 유지하며 MMI 창의 **한 화면으로** 또는 창 닫기로 복귀한다. 팝업이 차단되면 브라우저에서 이 사이트의 팝업을 허용한 뒤 다시 누른다.

## 공유되는 상태

관제 엔진·가상시계·전체 선로망·열차번호·시간표·시나리오·자동제어는 LS 창에서 한 번만 실행된다. MMI의 실제 DOM 노드를 새 창으로 옮겨 기존 이벤트와 편집 초안을 보존한다. 새 창에는 CSS만 불러오며 앱 스크립트나 두 번째 엔진을 실행하지 않는다. 역 선택·제어·스케줄 편집·로그는 같은 메모리를 사용한다.

`workspace-dom.js`는 두 문서의 요소 조회와 MMI 전역 메뉴 이벤트를 연결한다. LS 조작창과 우클릭 메뉴는 LS 문서에 유지한다. `workspace-windows.js`는 창 열기·포커스·스타일·닫기·복원을 담당한다. 새 창 닫기/탐색 시 MMI, 미확인 알람, 열린 MMI 확인창을 원래 문서로 돌리고 등록된 메뉴 이벤트를 정리한다.

## 메시지 표시 위치

| 메시지·조작 | 표시 창 | 다른 창 조작 |
|---|---|---|
| 경합·설정 거부 등 붉은 알람메시지 | MMI | LS 조작 및 시계 진행 가능 |
| LS 모드 전환·진로 선택·해정 확인 | LS | LS 확인 절차 유지 |
| LS에서 CCM 밖 제어를 요구한 오류 확인 | LS | MMI로 강제 이동하지 않음 |
| MMI의 스케줄 결과·확인·일괄정지 확인 | MMI | LS 조작 가능 |
| LS 우클릭·열차번호·표지판·Overview | LS | 기존 표시 위치 유지 |

MMI 일괄정지 확인을 연 뒤 LS에서 다른 역을 선택해도, 확인한 명령의 대상은 처음 선택했던 역이다. 열린 확인창의 대상과 실제 명령 대상이 바뀌지 않는다. 붉은 알람은 기존처럼 체크 후 확인해야 확인 처리되며, 창을 닫아 합쳐도 미확인 항목을 삭제하지 않는다.

## 사용 범위

별도 창은 같은 실습 세션의 보조 창이다. LS 원본 창을 닫거나 새로고침하면 실행 세션도 종료/초기화된다. MMI만 독립적으로 계속 실행하는 서버나 영구 저장 기능은 아니다. 브라우저의 팝업 허용과 사용자의 모니터 배치는 필요하며 운영체제의 창 위치를 강제로 지정하지 않는다. HTTP 로컬 서버의 Chromium에서 데스크톱 1440·1920px로 검증한다. 모바일은 지원하거나 검증하지 않는다.

## 검증

`python simulator/workspace-windows.browser.test.py`는 실제 팝업을 열어 두 문서의 제어·알람·모달 범위·시간 진행·스케줄 편집·시나리오 이동·메뉴 Escape·열린 확인창 복원·재분리·팝업 차단 복귀를 검사한다. MMI 창에는 두 번째 관제 엔진이 없음을 별도로 검사한다. 기존 MMI·그래프·시나리오·자동제어·진로 경합 시험도 함께 실행한다.
