# 참고: 철도 신호·관제 오픈소스 (2026-11-27)

GitHub의 비슷한 프로젝트를 받아 읽고(코드는 실행하지 않음) CTC LAB에 **참고할 설계만** 골랐다.
코레일 CTC의 LS·MMI·T/G·구술을 한데 묶은 오픈소스는 없었다. 아래는 부분적으로 겹치는 것들이다.

> **라이선스 주의**: 다섯 프로젝트 모두 GPL(v2·v3)이고 CTC LAB은 `UNLICENSED`(비공개)다.
> **코드·그림·데이터는 가져오지 않는다.** 아이디어와 동작 방식만 참고해 우리 코드로 새로 짠다.

## 가져올 만한 아이디어 (실습 효과 순)

### 1. 조치 필요 열차 목록 (RailOS 「Actions due」)
- **무엇**: 곧 관제사가 손대야 할 열차를 「조치까지 남은 시간」 순으로 최대 20개 보여 주는 작은 패널. 약 2초마다 갱신하고, 누르면 그 열차가 있는 화면으로 옮겨 간다.
- **우리에게**: CCM 역에 다가오는 열차(장내신호기 앞 도착 예정)와, AUTO 트러블에 걸린 열차를 한 목록으로 보여 준다. 누르면 해당 역 LS로 이동. 시험이 아닌 연습 모드에서만 켜는 보조 기능(본선 색 힌트처럼, FTS 중에는 잠금).
- **들어갈 곳**: `engine/autocontrol.js`(트러블·트리거 시각), `engine/train-status.js`(위치), 새 `ui/ls-actions.js`.

### 2. 운행 결과 채점 (TS2 `logAndScore…`)
- **무엇**: 열차가 역에 서면 **계획 착선과 다른 선에 도착했는지**, 늦었다면 **처음부터 있던 지연을 빼고 관제사 때문에 늘어난 지연만** 분 단위로 감점한다. 계획과 다른 곳으로 빠져나가면 「잘못된 진로」로 감점한다.
- **우리에게**: FTS·자유 연습의 결과 화면에 「착선 오류 · 관제사 지연(분) · 진로 오류」를 덧붙인다. 지금 채점은 「한 조작」 중심이라, 「결과」 쪽 근거가 생긴다. 실기3 경합 해소·대피 문제의 평가에 특히 맞는다.
- **들어갈 곳**: `engine/assessment.js`, `engine/scenario-flow.js`의 도착 처리.

### 3. 진로 거부 원인을 화면에 짚어 주기 (NXSYS 「Locking Conflict panel indications」)
- **무엇**: 진로가 설정되지 않을 때, 눈으로는 알기 어려운 원인(오버랩 쇄정된 전환기, 반대 방향 진로 등)을 제어반에서 깜빡여 보여 준다.
- **우리에게**: 지금은 「○○ 진로와 경합합니다」 같은 문장만 나온다. 연습 모드에서 거부 원인이 된 진로·전환기·궤도를 LS에서 2~3초 깜빡인다(시험 중에는 문장만).
- **들어갈 곳**: `engine/core.js`가 거부할 때 원인 요소 ID를 결과에 담고, `ui/ls-view.js`가 표시.

### 4. 무작위 지연·설비 고장 난이도 (RailOS 6.13 · TS2 DelayGenerator)
- **무엇**: 「없음·약간·보통·많음」 단계로 역 정차 지연, 전환기·신호기 고장, 임시 서행을 무작위로 일으킨다. 짧은 지연은 자주, 긴 지연은 드물게 생긴다. TS2는 `[(최소, 최대, 비율%) …]` 묶음으로 분포를 적는다.
- **우리에게**: 지금 설비 장애는 손으로 켜는 교육용 설정이다. 자동운행(AUTO) 연습에 난이도 선택을 더해 돌발 상황(지연 → 경합 → CDRS, 전환기 고장 → 트러블)을 저절로 만들고, LDTS 장애 → 계절체 연습과도 잇는다. 시드를 고정하면 같은 상황을 다시 연습할 수 있다.
- **들어갈 곳**: `engine/auto-controller.cjs`, `engine/equipment-controller.cjs`, 자동제어 설정 화면.

### 5. 진로 구분해정 (OSM Interlocking transit · TS2 route state 3)
- **무엇**: 열차가 지나간 뒤쪽 구간부터 쇄정을 차례로 푼다. 진로 전체를 한꺼번에 풀지 않는다.
- **우리에게**: 지금은 열차가 진로를 다 지나야 한꺼번에 해정된다. 구분해정을 넣으면 뒤따르는 진로를 더 일찍 설정할 수 있어, 시격·경합 연습이 실제에 가까워진다.
- **확인 필요**: 우리 LS 원본(전자연동)에서 진로 표시가 구간별로 꺼지는지 사진·영상으로 먼저 확인한 뒤 넣는다.

### 6. 전환기 전환 시간과 순차 전환 (OSM 「staggered point operation」)
- **무엇**: 전환기가 움직이는 동안 몇 초가 걸리고, 진로 하나에 여러 전환기가 있으면 전원 부담 때문에 차례로 움직인다.
- **우리에게**: 지금 전환은 즉시 끝난다. 전환 중 표시(몇 초) → 완료 뒤 신호 진행으로 바꾸면 「진로 설정 → 신호 현시」 사이의 실제 지연이 생긴다.
- **확인 필요**: 원본 LS의 전환 중 표시 모양(점멸·색)을 확인한 뒤 넣는다.

### 7. 시간표 경합 미리 분석 (RailOS 5.12)
- **무엇**: 시간표만 보고 「같은 착선에 같은 시각 도착」, 「n분 안에 연달아 출발」, 「승강장 수보다 많은 열차 체류」를 목록으로 뽑는다.
- **우리에게**: CDRS(`engine/cdrs.js`, `timetable.conflicts`)가 이미 운행 중 경합을 잡는다. 여기에 **오프라인 스케줄 편집기에서 [경합 분석]** 버튼을 더해, 실기1의 「경합이 없도록 임시열차 스케줄 작성」(5장 3절 마)을 저장 전에 스스로 점검하게 한다. 기존 경합 검지를 그대로 다시 쓴다.

### 8. 연동표 데이터 검증 (OSM Interlocking 설정 JSON + 스키마)
- **무엇**: 진로마다 요구 전환기(정·반위), 접근 구간, 해정 기점 구간, 반대 방향 진로를 표로 두고, 스키마로 형식을 검사한다.
- **우리에게**: 우리는 배선에서 진로를 뽑고 경합 쌍을 전수 대조한다(`engine/route-conflict-audit.cjs`). 같은 정보를 **역별 연동표 형식(진로 · 전환기 · 접근구간 · 경합 진로)으로 내보내는 도구**를 만들면, 원본 연동표와 사람이 직접 맞대 보기 쉬워진다.

### 9. 계전 조회식 「왜?」 보기 (NXSYS Relays | Query)
- **무엇**: 계전기를 고르면 지금 상태와, 그 계전기에 걸린 조건을 보여 준다.
- **우리에게**: 3번과 묶어, 신호기를 오른쪽 클릭 → 「진로 조건 보기」로 그 진로의 조건(전환기 정·반위, 궤도 비점유, 접근쇄정 남은 시간, 경합 진로)을 체크리스트로 보여 준다. 연동 원리를 공부하는 구술 대비 자료가 된다.

### 10. 선로용량·운전시격 계산 (OSRD)
- **무엇**: 선로·차량 성능으로 운전시분과 용량을 계산한다.
- **우리에게**: 실기3 「열차 계획」 편(야마기시·UIC·KNR 선로용량, 최소운전시격)은 계산 단원이다. OSRD를 그대로 쓰기보다, 교재 공식으로 **계산 연습 카드**(값을 넣으면 풀이 과정을 보여 주는 것)를 만드는 쪽이 시험에 맞는다.

## 참고만 하고 가져오지 않을 것
- **여러 클라이언트를 웹소켓으로 잇는 엔진 구조(TS2)**: 우리도 이미 엔진 하나에 LS·MMI·리모컨이 붙는 구조라 새로 얻을 것이 없다.
- **영국·미국식 신호 체계**(레버, NX 입출구 버튼, Call-on, Train stop): 코레일 CTC와 조작이 달라 그대로 옮기면 고증이 틀어진다.
- **배선 편집기(TS2·RailOS·NXSYS TLEdit)**: 우리 배선은 원본 LS 대조로 고정된 데이터라 편집기가 필요 없다.
