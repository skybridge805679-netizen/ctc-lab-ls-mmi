# 소스 구조: 엔진과 화면

데스크톱 프로그램이 되면서 사이트 시절의 한 폴더 구조를 둘로 나눴다.

```
desktop/          Electron 셸 (창 관리·메뉴·배치 저장). 렌더러에는 Node 권한이 없다.
simulator/
  index.html      진입점
  engine/         엔진(백엔드 역할): DOM을 쓰지 않는 순수 로직
  ui/             화면(프런트엔드): LS·MMI·열차 그래프·셸, 스타일
  e2e/            브라우저 통합 시험 (Playwright)
  assets/         배선도 이미지·오르페이아 이미지
tools/            원본 자료 → 엔진 데이터 생성·검수 스크립트
```

## engine/ (DOM 금지)
연동(`core`, `interlocking`, `route-menus`), 배선·선로망(`wiring`, `network`, `network-topology`, `track-network`, `line`, `train-windows`, `wings`, `schematic-details`), 시각표·자동제어(`timetable`, `autocontrol`, `scenario-motion`), 시나리오(`scenarios`, `emergency*`, `schedule-scenarios`), 운영 기록(`cdrs`, `ledger`, `practice`, `ls-operations`).
Node에서 `require`로 바로 시험할 수 있고(`engine/*.test.cjs`), 브라우저에서는 같은 파일이 `window.Sim*`로 노출된다.

## ui/ (엔진을 호출만 한다)
- `app.js` LS 화면과 조작 연결, `ls-view.js`·`ls-switches.js`·`fixed-symbols.js` LS의 SVG 그리기
- `mmi*.js`, `tg-tools.js`, `diagram-ui.js`, `schedule-ui.js` MMI와 열차 그래프·스케줄
- `shell.js`·`workspace-*.js`·`*.css` 창 구성

## 창 구성과 독립 엔진 (0.24.0)

Electron main이 `desktop/engine-process.cjs`를 utility 프로세스로 시작한다. `engine/runtime.cjs`가 관제 상태·시계·열번·시간표·선로망 운영·설비·자동운행·시나리오를 소유한다. LS·MMI·그래프의 UI는 `preload → main broker → engine` 명령과 스냅샷으로 연결한다. 실제 엔진에는 UI 디렉터리 의존성이 없다.

LS 창의 X는 숨기기이며 엔진은 계속 실행된다. LS 재불러오기도 같은 엔진에 다시 연결한다. MMI와 그래프는 같은 UI 문서 객체를 별도 OS 창으로 입양하지만 운행 상태와 시계는 utility 프로세스에서 실행한다. 프로그램 종료 메뉴를 실행하면 엔진도 종료한다.

그리기·창 구성·사용자 입력·내보내기 등 표현 계층은 UI에 유지한다. 일반 브라우저에서는 기존 로컬 실행을 유지하며, 데스크톱에서 연결이 끊겼을 때는 그 방식으로 우회하지 않는다. 0.24.0부터 utility 프로세스가 10초마다 압축 체크포인트를 원자적으로 저장하고 이전 백업도 보존한다. 메뉴 종료 때도 저장하며 재실행은 복구된 세션을 일시정지 상태로 연다. IPC는 버전별 변경분만 전달하며 시간표 편집 이력도 엔진이 소유한다.

0.25.0의 추가 LS 창은 같은 utility 엔진에 연결하는 신뢰된 렌더러다. 각 창의 선택역만 화면 로컬에 두며 알람 수신은 기본 MMI가 담당한다. 0.25.1에서는 역 사이 높이 제약을 계산하던 `ui/ls-alignment.js`를 삭제했다. `ui/ls-view.js`의 역별 좌표 변환은 0.24.0으로 복원하고 `ui/ls-seams.js`는 실제 본선 끝에서 창 끝까지 같은 높이의 수평 연장만 그린다. 이 표시 연장은 회로·연동·엔진 연결을 추가하지 않는다. [복원 범위·검증](v0.25.1-역별배치복원.md)
