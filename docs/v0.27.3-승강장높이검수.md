# v0.27.3 승강장 높이(황색=고상홈, 청색=저상홈) 반영 검수

v0.27.2의 반영을 원본 재현(LS/MMI 리버스 엔지니어링) 기준으로 검수했다.

## 과했던 것 → 줄임
| v0.27.2 | 문제 | v0.27.3 |
|---|---|---|
| LS 승강장 75개를 버튼(포커스 75개)으로 만들고 클릭 시 열차·취급목적을 고르는 비교 창 | 원본 LS에 없는 조작. 승강장이 열번창·선로 가까이 있어 클릭을 가로챔 | 승강장은 정적 표시. 마우스를 올리면 `황색 승강장 · 고상홈`만 보임. 범례는 유지 |
| MMI 열차스케줄(CA028_02)에 `대응 홈 높이` 칸 추가, 기본값 `미확인` | 원본 화면에 없는 입력칸. 모든 열차가 미확인이라 정보가 실제로 쓰이지 않음 | 칸 삭제. **열차등급이 기본값을 정한다**: 전동열차=고상홈, 일반열차·KTX=저상홈, 회송열차=승하차 없음. 시간표 JSON/세션에 `boardingHeight`가 기록돼 있으면 그 값이 우선(예전 파일 호환) |

열차 속성 조회의 `대응 홈 높이` 행은 열차등급에서 정한 값으로 계속 보여 준다.

## 모자랐던 것 → 보강
- **선로와의 연결이 없었다.** 승강장 색을 시설 정보로만 두고 어느 선로에 붙은 홈인지 보지 않아, 시간표의 정차선이 홈 높이와 맞는지 검사하지 않았다. 각 승강장 표시가 위·아래 가장 가까운 선로(섬식은 양쪽)를 담당한다고 보고, **정차하는 열차의 도착선이 그 열차등급의 홈 높이와 맞는지** 시험(`ui/platform-tracks.test.cjs`)으로 확인한다.
- 이 검사로 **영등포 상행 전동열차가 저상홈(청색)인 2T에 정차**하던 오류를 찾았다. 자동 추정 진로가 `2B_2T`로 도착한 뒤 7T의 `3A`로 출발하는, 물리적으로 이어지지 않는 조합이었다. 출발 신호기가 서 있는 선로로 도착하도록 추정 규칙을 고쳐 `2A_7T → 3A_B941T`(7T는 고상홈)가 됐다.

## 확인이 필요한 것 → v0.27.4에서 확정

사용자가 LS에서 진로를 설정해 확인했다: 의왕 `2A_6T → 3A_B1011T`, 금정 `2A_4T → 3A_B993T`. 아래는 당시 기록이다.

MMI 사진에서 읽은(`photo`) 상행 진로 두 곳은 도착선과 출발 신호기의 선로가 다르다. 사진값이라 임의로 고치지 않았다.
- 의왕: `2B_6T` 도착, `3B_B1011T` 출발 — 3B는 5T, 6T에는 3A가 있다.
- 금정: `2A_4T` 도착, `3B_B993T` 출발 — 3B는 3T, 4T에는 3A가 있다.
