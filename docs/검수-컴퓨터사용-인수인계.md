# 검수 인수인계 — 컴퓨터 사용으로 실기 한 파트 직접 치르기

이 문서는 **새 채팅의 Claude(컴퓨터 사용 가능)**가 읽고 바로 검수를 시작할 수 있게 쓴 것이다. 이전 대화를 몰라도 된다.

## 1. 무엇을 하는가
- 사용자의 맥에 설치된 **ORPHEIA CTC LAB**(철도관제 LS·MMI 실기 연습용 데스크톱 앱, 최신판)으로 실기 시험 한 파트를 직접 치른다.
  - 경합 해소 1건
  - 석수 충돌(비상시 조치 03) 1건
- Claude는 말을 할 수 없다. 그래서 관제사가 무전·전화로 **말하는 통보·지시·판단을 열어 둔 「메모」 앱에 타이핑**하며 진행한다.
  - 예: `(관) K0450열차, 관제 이상! …`
  - 예: `[판단] 인접선 지장 여부 확인 전이라 하선 열차 통제부터`
- 목적은 **검수**다.
  - 실제 교육생처럼 써 보며 막히는 곳, 원본과 다른 곳, 버그, 불편한 화면을 찾는다.
  - 점수를 잘 받는 것이 목적이 아니다.

## 2. 앱 구조 (먼저 알아야 할 것)
| 창 | 누가 쓰나 | 여는 법 |
|---|---|---|
| **LS** (현장설비 배선도) | 교육생 | 앱 시작 시 자동 |
| **MMI** (열차스케줄·열번·T/G 등 메뉴) | 교육생 | 자동, 또는 메뉴 「실습 화면 → MMI 창으로」 ⌘2 |
| **열차 그래프(T/G)** | 교육생 | MMI 「열차스케줄 → 온라인 열차그래프」, 또는 ⌘3 |
| **FTS 제어통제** | **교수** (교육 시작·통보 확인·상황 변경 주입) | LS 상단 「↗ FTS」, 또는 ⌘4 |
| **문제 발생** | 교육생 (문제명칭·상황·조치사항) | FTS가 문제를 내면 자동으로 뜸 |

- LS 조작
  - 신호기를 누르면 진로 선택이나 정지 확인이 뜬다.
  - 상단 AUTO/CCM은 역제어모드 전환이다. 진로·정지는 CCM에서만 된다.
  - 열번창을 우클릭하면 열차번호 입력·수정·이동·삭제를 한다.
- **접근쇄정**: 장내신호 정지 후 90초(출발 30초) 동안 진로가 풀리지 않는다. LS 상단 「+10초」로 시간을 넘길 수 있다.
- **알람**: MMI 하단·팝업의 알람메시지는 **체크한 뒤 [확인]**해야 확인 처리된다(✕는 닫기일 뿐). 열차번호 중복 알람(충돌·구원연결) 확인은 채점 항목이다. 알람이 뜨면 바로 읽고 확인하고, 메모에 `[알람] 내용 → 확인`으로 남긴다.
- **단선지령식**: 별도 버튼이 없다. LS에서 반대선으로 나가는 진로를 내고 열번을 옮기면 된다(실제처럼). 앱이 알아서 맞은편 출발을 막는다.

## 3. 준비 (교수 역할) — FTS에 검수용 시나리오 넣기
1. FTS 창을 연다(⌘4). 왼쪽 **시스템관리**로 간다.
2. JSON 입력칸에 아래를 붙여 넣는다.

   ```json
   {"version":1,"problems":[],"schedules":[],
    "situations":[{"id":"S-CHECK-1","name":"검수 · 경합해소","problems":["P-sch-conflict"]},
                  {"id":"S-CHECK-2","name":"검수 · 석수충돌","problems":["P-em-03"]}],
    "scenarios":[{"id":"SC-CHECK","name":"검수 · 경합해소 + 석수충돌","situations":["S-CHECK-1","S-CHECK-2"]}]}
   ```

3. **「검사 후 합치기」**를 누른다.
4. **교육설정**에서 다음과 같이 고르고 **교육 시작**을 누른다.
   - 「시나리오 선택」: 「검수 · 경합해소 + 석수충돌」
   - 교수 001 · 교육생 tester
   - 실제 시험처럼 하려면 「교육생 문제 발생 화면에 조치사항 표시」를 끈다.
5. **모니터링관리** 화면이 교수용이다.
   - 문제는 **모든 목표 ✔ + 모든 통보 [확인]**이 되어야 「완료」로 끝난다. 통보를 일부만 확인하면 목표를 다 채워도 시간초과까지 간다. 메모에 쓴 통보에 해당하는 항목을 빠짐없이 확인한다.
   - 교육생이 말한 통보는 여기서 [확인]한다. 메모에 쓴 문장을 보고 Claude가 교수로서 확인한다.
   - 「상황 변경 [주입]」으로 감독관 역할(조건 변경)을 한다.
   - 「제어통제 로그」에 진행이 남는다.

## 4. 문제 1 — 경합 해소 (P-sch-conflict, 제한 10분)
- 임시열차 **B0000**이 하행 앞 열차를 따라잡아 경합이 생긴다.
- **해소 원칙**
  - 경합 위치에서 가장 가까운 **앞쪽(상류) 해소역**에서 B0000의 시각을 **+2분** 늦춘다.
  - 같은 해소역에서 **도착진로·출발진로**를 바꿔 해소한다.
  - 해소역은 용산 · 영등포 · 금천구청 · 안양 · 군포 · 의왕이다.
  - 다른 열차와 3차 경합이 생기면 안 된다.
  - 최소 운전시격은 120초다.
- **흐름**
  1. MMI 「열차스케줄 → 온라인 열차그래프」에서 열차를 검색하고, 십자선·돋보기로 경합 구간을 찾는다.
  2. 「열차스케줄 관리(수정)」에서 B0000의 해소역 출발시각·진로를 고친다.
  3. 편집적용한다.

## 5. 문제 2 — 석수 충돌 (P-em-03, 제한 15분 — 앱이 12:00으로 보이면 옛 라이브러리이니 앱을 최신판으로 다시 시작한다)
- **상황**: 석수역 상선에서 K0450을 후속 K0452가 추돌했다(구원·운행선 변경·회송).
  - 취급역은 안양·금천구청이다.
  - 석수는 비연동 중간역이라 금천구청 LS에 보인다.
- **순서는 정해져 있지 않다.** 목표를 순서 없이 채점하므로, 상황을 보고 무엇을 먼저 지시할지 판단한다.
- **원본 대본의 주요 조작** (참고 — 원본 대본 순서는 예시일 뿐)
  - K0450 → **G0450** 열차번호 수정 (회송)
  - 안양 CCM → **3B 정지**
  - 금천구청 CCM → **2A 정지**
  - 금천구청 **2B-5T** 장내 진행 → AUTO — **K0456을 상1선으로 운행선 변경해 받는 진로**다(원문 270~275행). G0450용이 아니다. 5T에 열차가 있으면 연동이 거부한다.
  - 안양 **3B-B655T** 출발 진행 → AUTO (상1선 방면, K0456 운행선 변경)
  - K0454 → **G0454** (구원열차) → K0452가 있는 석수 열번창으로 이동(구원연결, 번호 중복 알람 확인) → G0454 삭제
  - K0452 → **G0452** (회송)
  - 사고 순간 MMI의 **K0450+K0452 열차번호 중복 알람 확인**, 구원연결 뒤 **중복 알람 확인**
  - 두 역은 끝날 때 **AUTO**여야 한다.
  - 이 문제는 대본에 나오는 열차만 있는 상태로 시작한다(기본 시간표 열차는 비워진다).
- **통보·지시**: 상황수보, 인접선·후속·선행 열차 통제, 초기대응팀·전파/보고, 구원 지시, 운행선 변경 통보, 합병 승인, 회송, 복구완료 보고 등을 메모에 쓴다.
- **상황 변경**: 교수로서 하나쯤 주입해 보고, 대응이 바뀌는지 본다. 이 문제에 있는 분기는 다음과 같다.
  - 인접선 지장 확인 불가
  - K450 회송 불가
  - G450 발차 후 운행선 변경
  - 제동관 파손
  - 탈선

## 6. 기록과 보고
- **메모 앱**: 시험 중 통보·판단을 시간 순서로 쓴다. 맨 위에 `[검수] 날짜 · 버전`을 적는다.
- **검수 결과** (메모 끝에, 그리고 채팅으로 사용자에게)
  - 각 문제의 결과: 완료/시간초과, 점수, 남은 목표
  - 막힌 곳과 그 이유. 어떤 화면에서 무엇을 기대했는데 무엇이 나왔는지.
  - 원본(실제 관제 프로그램·교재)과 다르다고 느낀 점
  - 버그로 보이는 것: 재현 순서와 스크린샷 설명
- 이 채팅에서 코드를 고칠 필요는 없다. 결과를 사용자가 개발 채팅으로 가져간다.
