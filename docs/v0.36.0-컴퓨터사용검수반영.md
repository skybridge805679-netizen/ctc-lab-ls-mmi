# v0.36.0 — 첫 컴퓨터 사용 검수 반영 (2026-11-01)

맥에 설치한 v0.35.0으로 Claude가 컴퓨터 사용으로 실기 한 파트를 직접 치렀다(경합해소 1건, 비상 03 석수 충돌 1건). 사용자도 그 과정을 지켜보며 지적했다. 그 결과를 반영한다. 검수 방법은 `docs/검수-컴퓨터사용-인수인계.md`에 있다.

## 사용자 지적
- **K1002가 충돌 지점에 있던 이유**: 비상 문제 중에도 기본 시간표 열차(K1002·K1004·K1006 등)가 시간표대로 달려 사고 구간에 들어갔다. 관제사의 열차통제 지시는 말로 하므로 시뮬레이터가 그 열차들을 세우지 못한다.
  - 대피·비상 문제는 이제 **대본에 나오는 열차만** 남기고 시작한다. 초기 상태에 `clearTimetable`(시간표 비우기)을 넣었다.
- **알람 확인 과정이 없던 것**: 대본의 「구원연결 → 열차번호 중복 알람 확인」을 채점하지 않았고, 인수인계 문서에도 없었다.
  - MMI 알람을 체크하고 [확인]하면 엔진에 기록되고, FTS 조건 `alarmAck`로 채점한다.
  - 사고 순간의 중복 알람 확인과, 구원연결 뒤의 중복 알람 확인이 비상 문제의 목표가 됐다.

### 함께 고친 것
- 비상 05: 원문은 「A0168열차 : 구로역 발차」인데 A0168을 구로 5T에 세워 둔 채였다. 그래서 K1212를 받는 2B-5T가 막혔다.
  - 이제 A0168은 사고와 함께 출발한다.
- 대본 초기 진로는 열번창에 열차가 있는 선로로 들어가는 진로를 고르지 않는다.

### 그대로 둔 것
- **금천구청 2A 정지 시 접근쇄정이 걸리지 않은 것**
  - 이 시뮬레이터의 접근구간은 장내신호 바로 바깥 폐색 회로 하나다. 금천구청 2A의 접근구간은 B965T다.
  - K0450이 있던 B967T(석수)는 그보다 한 구간 더 밖이라 접근 열차로 보지 않는다.
  - 실제 접근구간 길이는 교재 근거를 더 찾아 정해야 한다.
- **시험 남은 시간과 문제 남은 시간이 다른 것**: 통합 시험 시간(60분)과 문제별 제한시간은 원래 다른 기준이다.
- **중복 알람이 LS에 안 뜨는 것**: 알람은 MMI 기능이다. LS는 열번창에 두 번호를 함께 표시한다.
- **T/G 6시간 범위·선택 열차 강조**: 다음 작업으로 둔다.
