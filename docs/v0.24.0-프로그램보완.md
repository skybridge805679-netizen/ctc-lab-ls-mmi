# v0.24.0 — 프로그램 기능 보완

15개 취급역의 LS 배선을 창의 가로·세로 공간에 맞춰 배치한다. 기존 선로·회로 코드·신호·열번창 수는 보존하며, 중간역명은 열번창 위에 둔다. 배선·쇄정 진로·전환기 형상·클릭 좌표는 같은 변환을 사용한다. 창 크기가 바뀌면 배치를 다시 계산하고 SVG 자체는 가로세로 같은 비율로 표시한다. 작은 창 시험은 데스크톱 창 축소 시험이며 모바일 화면을 추가한 것이 아니다.

## CCM 선로전환기 A/B 제어

CCM에서 `51A` 같은 표기를 누르면 “선로전환기 SW_51A 를 반위 제어를 하시겠습니까?” 확인창을 연다. 승인하면 엔진 명령으로 N/R 상태와 배선 연결 형상을 바꾼다. 현재 반위이면 정위 전환을 묻는다. 키보드 Tab·Enter/Space로도 조작한다. 진로·오버랩·수동 쇄정과 장애 상태의 전환은 거부한다.

쌍동기는 A/B가 같은 제어 상태를 사용한다. 근거는 업로드된 [교통관제운영 1권](../references/textbooks/교통관제운영_01_001-114.pdf)의 **PDF 114쪽** 선로전환기 전환 설명 “쌍동 선로전환기의 경우 A/B선로전환기가 동시에 전환된다.”이다. 사용자가 요청한 웹 검색도 시도했으나 이 실행 환경의 검색 도구 부재와 외부 검색 사이트 접속 차단으로 웹 자료는 확보하지 못했다. 따라서 업로드된 교재와 원본 LS 캡처를 근거로 삼았다.

금천구청 원본 사진의 51A/B는 아래 왼쪽에서 위 오른쪽으로 이어지는 건넘선이다. 기존 기하 데이터의 내부 번호가 반대로 붙어 있어 소스 표기 `51A/B → 내부 52`, `52A/B → 내부 51`로 연결한다. 의왕도 [원본 슬라이드 17](../simulator/assets/stations/slide17.png)과 대조하여 같은 번호 차이를 보정했다. 내부 경로/연동 번호를 일괄 변경하여 기존 진로를 손상시키지 않는다. 원본에 확인된 A/B 표기 129개와 기존 숫자 제어점을 지원한다. 알려지지 않은 단독/쌍동 설비를 외형만 보고 추가하지 않았다.

## 시나리오와 열번 이동

대사·보고 단계는 체크박스 없이 가상시계에 따라 자동 진행한다. 대사 길이에 따라 3–18초를 배정하는 **교육용 시간 모델**이다. 실제 음성 통신 인식은 아니다. 진로 설정·일괄정지·구원 등 사용자가 해야 하는 조작은 엔진 상태를 검사하여 기다리고, 조건이 충족되면 이동 작업을 시작한다. 시계 배속이나 +10초에서도 이동·점유 단계를 건너뛰지 않도록 시나리오 활성 중에는 1초 단위로 계산한다.

열번창 메뉴의 ‘열차번호 이동’은 선택한 창으로 즉시 이동한다. 해당 번호에 예약된 시나리오 이동을 취소하므로 시간이 지나 원위치로 돌아가지 않는다. ‘교환/삭제’에도 같은 규칙을 적용한다. 자동운행·시나리오의 물리적 이동은 별개로 시간·진로·점유를 사용한다. 실제 운행 중의 붉은 점유 현시는 유지한다.

## 파일·편집·세션

- 열차 그래프의 파일 열기/저장: 시간표 JSON을 가져오거나 내보낸다. 파일 크기 64MB, 열차 20,000편 한도에서 역·시간·중복 번호·운행일을 원자적으로 검증하고 교체한다. 빈 시간표도 표시할 수 있다.
- 실행 취소/다시 실행: 시간표 편집의 열차별 변경 전후를 보관한다. 최대 100건·64MB 예산을 사용한다. 한 작업이 예산을 넘으면 그 한 건은 남긴다. 자동운행 등으로 해당 데이터가 달라졌다면 오래된 이력으로 덮어쓰지 않는다. 그래프에서 Ctrl/Cmd+Z·Shift+Z를 사용하며 입력창의 일반 문자 편집도 유지한다.
- 엔진 세션: utility 프로세스가 10초마다 사용자 데이터 폴더의 `engine-session.orpheia`에 저장한다. 종료 메뉴에서도 저장한다. 체크포인트를 gzip 압축하고 SHA-256 무결성을 검사한다. 임시 파일 동기화 후 원자적으로 교체하며 직전 파일을 `.bak`으로 보관한다. 주 파일 손상 시 백업을 복구하고 알린다. 둘 다 읽을 수 없으면 원본 파일을 남기고 새 세션으로 시작한다.
- 실습 화면 메뉴의 ‘실습 세션 저장/열기’: `.orpheia` 파일을 별도 저장·불러온다. 역별 상태·열번·시간표·쇄정·자동운행·시나리오 이동·공통설비 장애·경과시간을 엔진에서 저장한다. 재실행/불러오기는 **일시정지** 상태로 시작한다. 창 배치와 화면 개인 설정은 기존 저장 경로를 사용한다. 시간표 편집 취소 이력은 실행 중에만 보존한다.
- LS 창의 X는 숨기기, MMI 창의 X는 숨긴 문서로 보관하기이며 엔진을 종료하지 않는다. 프로그램 종료는 메뉴에서 수행한다. 강제 종료 직전 10초 이내 변경은 마지막 자동 저장 이후일 수 있다.

## 대용량 엔진과 측정

엔진은 별도 프로세스에서 실행한다. 상태 버전에 따라 변경된 부분만 IPC로 보낸다. 변경 없는 시간표를 매번 복사·직렬화하지 않으며, 누락된 버전 구간은 합쳐 보내고 첫 연결은 전체 상태를 보낸다. 충돌 검사는 역/시간 인덱스로 후보를 좁힌 뒤 기존 판정식을 적용한다. 순서 역전, 부분 취소, 같은 시각도 기존 전수 비교 결과와 대조했다.

[측정 원본](benchmarks/engine-v0.24.0.json)은 Linux·Node 24.19.0에서 `node tools/benchmark-engine.cjs 10000`으로 얻었다. 시간표 열차 10,000편·정차 20,000건·충돌 19,312건에서 가져오기 약 158ms, 충돌 조회 약 44ms였다. 최초 전체 상태 약 7.71MB, 변경 없는 조회 46바이트, 1초 진행 후 변경분 약 151KB였다. 이는 해당 장비의 시간표/전송 측정이며 실제 열차 1만 편의 동시 물리 운행 성능을 의미하지 않는다.

## 검증과 남은 자료 범위

Node 단위/통합 시험, 모든 역의 표시된 전환기 실제 클릭, N/R 상태의 글자 겹침·잘림 검사, 6개 데스크톱 창 크기 × 15개 역 비례 표시, 대사 자동 진행·9종 비상 이동, 수동 즉시 이동, 시간표 파일 선택/다운로드·취소/재실행을 검증했다. 독립 엔진 실제 프로세스와 종료 후 재시작 복구, 손상 파일의 백업 복구/잘못된 파일 거부도 시험한다. 패키지 파일은 원본과 바이트 단위로 대조한다.

이 환경에서는 Linux Electron을 실제 실행하고 Mac ARM64·Windows x64 패키지 디렉터리 생성을 확인한다. **Mac/Windows 네이티브 실행과 설치본 생성 결과는 main 반영 후 해당 OS의 GitHub Actions에서 확인해야 한다.** 양쪽 네이티브 검증/빌드가 성공하면 v0.24.0 릴리스를 생성한다.

기지 내부 배선/연동표, 실제 설비의 상세 안전 조건, 원본 미확인 메뉴 의미와 음성 통신 자동 인식은 이번 범위에서 만들어 내지 않았다. 본 프로그램의 교육용 이동·시간 모델을 실제 관제 시스템의 인증된 동작과 동일하다고 보장하지 않는다.

### 이번 변경의 검증 기록

- `npm test`: 64개 테스트 통과. 충돌 인덱스는 100개 무작위 데이터셋을 기존 전수 비교와 대조했다.
- 데스크톱 브라우저 22개 스위트 통과: MMI·창 고정·TG 도구·대피/비상/시간표 시나리오·캐스팅·AUTO·경합·전체망·회로망·LS 헤더/전환기/고정표식/배치·설비·경합연습·재생·창 축소·신규 프로그램 기능.
- Linux Electron 소스 실행과 ASAR 패키지 실행: LS/MMI/그래프 제어, 독립 PID, 렌더러 정지/닫기/다시 불러오기 중 운행 유지, 종료 후 새 프로세스로 복구를 확인했다.
- Linux·Windows x64·Mac ARM64 ASAR 각각 런타임/에셋 105개를 소스 바이트와 대조했다. Windows/Mac 네이티브 OS 실행 검증과 서명은 이 로컬 검증에 포함하지 않는다.
