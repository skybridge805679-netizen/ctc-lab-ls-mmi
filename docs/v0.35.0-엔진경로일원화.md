# v0.35.0 — 화면은 엔진 하나만 본다 (브라우저 전용 계산 경로 제거) (2026-11-01)

## 왜
데스크톱 앱(Electron)은 시뮬레이션 엔진(`simulator/engine/runtime.cjs`)을 별도 프로세스에서 돌린다. 화면은 `OrpheiaEngine.request(...)`로 명령을 보내고 상태를 받는다.

그런데 화면 코드에는 `index.html`을 브라우저에서 직접 열 때를 위한 **두 번째 경로**가 남아 있었다. 화면 안에서 직접 계산하는 경로다. 대상은 열차 자동제어, 시나리오 대본 진행·열차 이동, FTS 교육 진행·현상 적용·채점, 장애 설정, 경합해소 출제·채점, 시험 시간 등이다.

기능을 고칠 때마다 두 경로를 맞춰야 했고, 실제로 두 경로의 동작이 어긋나기도 했다. 자동 시험(e2e 53개)이 이 브라우저 경로로 돌아서, 시험이 데스크톱 앱과 다른 코드를 검증하고 있었다.

## 무엇을 바꿨나
- **`ui/page-engine.js`**: 데스크톱 앱이 아닐 때 같은 `runtime.cjs`를 페이지 안에서 돌린다. 연결 형식도 데스크톱과 똑같이 `request(action, since, version)`다. 엔진 모듈은 CommonJS 그대로 읽는다.
  - 브라우저 전용 계산은 없다. 다른 것은 연결 방식(IPC 대신 페이지 안 호출)뿐이다.
  - 세션 파일 저장·열기는 데스크톱에서만 된다.
- **화면 모듈의 로컬 분기 삭제**
  - `app.js`: 로컬 시계·로컬 조작 기록.
  - `assessment-ui.js`: 로컬 시험 시간.
  - `autocontrol-ui.js`: 화면 쪽 열차 자동제어 엔진·열번 이동 전체. 135줄 → 38줄.
  - `mmi-scenarios.js`: 로컬 대본 시작·채점·열차 이동.
  - `fts.js`: 로컬 교육 진행·현상 적용·채점·로그.
  - `equipment.js`: 로컬 장애 상태·표준시각 전송.
  - `ls-context.js`: 로컬 열번창 모델.
  - `mmi-drill.js`: 로컬 출제·채점.
  - `mmi.js`: 로컬 중복 알람.
  - `remote-engine.js`: 엔진 없이 계산하던 대체 경로.
- 쓰지 않게 된 `engine/session.js`·`engine/scenario-flow.js`를 페이지에서 뺐다. 엔진은 계속 쓴다.

## 일원화로 드러나 고친 것 (데스크톱 앱에도 해당)
- 역 초기화로 사라진 진로가 MMI에 「해정」으로 기록되던 문제.
- 시나리오·FTS 시작이 시계를 다시 움직여도 일시정지 버튼 표시가 늦게 바뀌던 문제. 이제 매번 엔진 시계를 따른다.
- 엔진 상태가 그대로여도 1초마다 LS를 통째로 다시 그리던 문제. 이제 엔진 상태판이 바뀔 때만 그린다.
- 역을 바꿀 때마다 실기 시나리오 창이 대본도 없는데 화면 상태를 엔진에 보내던 문제. 이 때문에 엔진이 불필요하게 다시 그렸다.
- 시나리오 열차(시간표 밖 번호)의 실제 위치를 화면이 계산하던 것. 이제 엔진이 낸다.
- FTS 제어통제 로그에 문제 발생이 「문제 발생 · 문제명」으로 남는다.
- (v0.34.0 이후 핫픽스) 다음 문제가 뜰 때마다 「문제 발생」 창이 포커스를 가져가 LS 우클릭 메뉴가 닫히던 문제.

## 시험
- e2e 시험이 화면 쪽 시간표·상태를 직접 고치던 곳을 엔진 명령으로 바꿨다(`timetable import`, `tick` 등). 엔진 시계 기준으로 기다리게 했다.
- 선로망 창·로컬 자동제어를 전제한 단계는 엔진 기준으로 다시 썼다.
- 자동 시험이 데스크톱 앱과 같은 엔진 코드를 지나간다.
