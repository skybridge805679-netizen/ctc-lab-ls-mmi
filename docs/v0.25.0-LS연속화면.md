# v0.25.0 — 여러 LS 창을 수평으로 이어 보기

하단 **LS +** 또는 프로그램 메뉴 **실습 화면 → LS 추가 창 → 역**으로 LS 창을 추가한다. 추가 창은 선택역을 따로 유지하며, 같은 관제 엔진에 제어 명령을 보낸다. 예를 들어 구로와 금천구청을 나란히 두고 서로의 역 선택을 바꾸지 않은 채 조작할 수 있다. 동일 역을 여러 창에서 열면 상태도 공유한다.

창의 콘텐츠 크기와 위쪽 위치를 같게 배치하면 같은 본선이 화면 경계의 같은 높이에서 이어진다. 서로 다른 크기의 창은 각자 비례 배치하므로 물리적 픽셀 높이가 같다는 보장은 없다. 모니터 사이의 화면 배율·운영체제 화면 배치가 다르면 창의 실제 표시 크기도 맞춰야 한다. 모바일 화면은 추가하지 않았다.

## 정렬 방식

원본에서 수평인 선로 묶음을 노선 전체의 배치 제약으로 함께 계산한다. 인접 화면의 같은 본선에 속한 경계 묶음은 같은 행을 공유하고, 각 역 안에서 겹치는 가로 구간의 위아래 순서를 보존한다. 불필요한 행 여유를 줄여 공통 본선의 간격을 정돈한다. 이는 표시 좌표 계산이며 엔진의 회로·진로·쇄정·물리 연결을 변경하지 않는다.

경계는 원본 선로 끝에서 화면 끝까지 **같은 높이의 수평 직선**만 연장한다. 맞추기 위한 곡선·대각선·계단 꺾임을 덧붙이지 않는다. 원본 구내에 있던 높이 변화·건넘선·분기와 기지 선로는 유지한다. 노선의 시작/끝처럼 이웃 연결이 없는 쪽에 임의 본선을 만들지 않는다. 금정의 일반선처럼 해당 역에서 직접 취급하지 않는 통과선도 포함한다.

그려지는 선로·신호기·전환기·열번창·회로 코드·쇄정 진로에 같은 좌표 모델을 적용한다. 흰 직사각형 열번창을 추가 회로로 오인하여 배치 제약에 넣지 않는다. 신호기 쌍은 가독성에 필요한 간격을 두고, 회로 코드와 열번창이 빽빽한 곳은 같은 선로 가까이에서 글자와 입력창을 정렬한다. 경계 연장의 색은 끝 회로의 진로·점유 상태를 따른다.

## 추가 창과 MMI

추가 LS 창은 별도의 시뮬레이터를 실행하지 않는다. 신뢰된 Electron 창만 같은 utility 엔진에 IPC 명령을 보내며, 각 창은 독립적인 상태 버전과 이벤트 커서를 사용한다. 추가 창의 역 전환은 다른 LS 창이나 기본 MMI의 선택역을 변경하지 않는다.

추가 LS의 **MMI 창**·**열차그래프 창** 버튼은 기본 창의 기존 MMI/그래프를 연다. 엔진의 붉은 알람은 기존 MMI에 전달하며 추가 창마다 알람을 복제하지 않는다. 제어 확인은 조작한 LS 창에 표시한다. 추가 창을 닫아도 기본 LS·MMI·엔진은 계속 실행되고, 추가 창의 위치·크기도 저장한다.

## 검증

- Node 시험 69개 통과. 실제 수평 구간의 수평 유지, 인접 경계의 동일 행, 경계 연장이 두 끝점으로 된 수평선이라는 회귀 검사를 포함한다. 658개 진로의 표시와 118개 전환기 그룹의 형상 회귀도 유지한다.
- 1920×1080·1440×1000·960×720에서 14개 인접 경계 모두 같은 본선의 끝점 높이 차이 0.5픽셀 미만, 가로 창 끝 오차 1픽셀 미만을 검사했다. 실제 추가 Electron LS 창 두 개에서도 높이를 대조했다.
- 15개 역의 N/R 상태에서 모든 글자 겹침/잘림, 원본 경계 괄호·기지 설명·열번창, 6개 데스크톱 창 크기의 비례 표시를 검사했다.
- 실제 추가 창에서 제어 후 기본 창에 반영됨, 같은 엔진 PID, 다른 창의 역 선택 유지, 기존 MMI 재사용, 창 닫기 후 엔진 유지와 세션 복구를 검사했다.
- Linux Electron 실제 실행과 ASAR 실행을 검증하며 Mac ARM64·Windows x64 패키지 내용은 런타임/에셋 107개를 소스 바이트와 대조했다. Mac/Windows 네이티브 실행·설치본 생성은 main 반영 후 해당 OS의 Actions 검증 대상이다.
